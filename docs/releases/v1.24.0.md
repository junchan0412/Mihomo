# Mihomo v1.24.0

`v1.24.0` 聚焦配置资源与远程覆写的批量刷新路径：消除所选操作的串行等待，限制并发写入，并将批量提交收敛为稳定、可验证的 Store 层行为。

## UI 与 UX

- 配置资源页的“全部更新”“更新所选”和“回滚所选”均遵守顶部的并发设置；操作运行时会禁用重复入口、双击与右键更新，避免同一资源被并发替换。
- 远程覆写的所选刷新和全部刷新会显示包含并发数的状态，并在运行期间忽略重复请求。
- 资源页继续在实际配置中呈现 Proxy 6、Rule 107 共 113 项资源，批量控制与可访问性标签均可见。

## 性能与稳定性

- 新增 `BoundedConcurrentWork`：在上限内持续补充任务，输出严格按输入顺序归并，避免分批空闲和历史顺序不稳定。
- Provider 批量更新/回滚仅在所有 worker 返回后一次写入更新历史；113 项资源不再产生逐项 history 文件写入。
- 全量 Provider 更新复用同一调度器，并避免 Geo 更新前一次无意义的配置资源重解析。
- 远程覆写刷新使用订阅刷新并发设置，下载后合并并一次提交 `config-fragments.json`，失败不覆盖原内容。

## 架构与测试

- 资源与覆写批量协调各自拆入独立的 `AppStore` extension；资源基础操作、批量协调和通用执行器均低于 350 行维护性告警阈值。
- `ProviderItem` 与 `ConfigFragment` 具备明确的 `Sendable` 边界，worker 不接触 `MainActor` UI 状态。
- 新增并发上限、非正并发钳制、稳定输出顺序和不可刷新资源过滤测试。
- `swift test`：214/214 通过；`git diff --check` 通过；维护性审计覆盖 225 个 Swift 文件，0 warning、0 over-max，最大文件 `MenuBarView.swift` 为 347 行。
- 使用 `APP_VERSION=1.24.0 APP_BUILD=78` 构建并启动 `dist/Mihomo.app`，并实机检查资源与覆写工作区。

## 无开发者账户发行说明

本版本使用 ad-hoc 签名，未经过 Apple notarization。下载、解压并移动到 `/Applications` 后，如 macOS 阻止启动，请执行：

```bash
xattr -cr /Applications/Mihomo.app
```
